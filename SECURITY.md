# Security

Ressac is a browser that lets an AI agent read and act on web pages. Security reports are welcome and taken seriously.

## Reporting a vulnerability

Please **do not open a public issue**. Report it privately through GitHub: the repository's **Security** tab › **Report a vulnerability**.

Include what you can: the Ressac version (Réglages › À propos), steps to reproduce, and what an attacker gains. You will get an answer as fast as possible. Ressac is a small project in beta: there is no bug bounty.

Bugs in Firefox itself (Gecko, SpiderMonkey, the network stack) belong to [Mozilla's security program](https://www.mozilla.org/security/), unless one of Ressac's patches causes them.

## Supported versions

Only the latest released version gets fixes. Ressac updates itself.

## What Ressac protects

The design assumes **web pages are hostile, including the ones the agent reads**: a page can try to give the agent instructions (prompt injection). The protections, in short:

### Where the agent runs

- **In a container inside a small Linux VM**, not on your Mac (Lima, Apple Virtualization, rootful Podman; `apps/firefox/scripts/vm/lima.yaml`, `apps/firefox/host/machine.ts`). The VM sees only the Ressac folder (read-write) and the workflow engine's folder (read-only), never your home folder; it forwards to the Mac only the Podman socket and ports 5300-5319 on `127.0.0.1`. The VM image is pinned by SHA-256. A Docker engine you installed is still used as a fallback: the container and its mounts are the same, but that engine's own VM shares more of your Mac (Docker Desktop shares `/Users` with it by default), so an escape from the container would reach further. Lima's SSH port listens on the Mac's localhost only; your `~/.ssh` keys are not authorized and no SSH agent is forwarded into the VM. `apps/firefox/scripts/vm/security-check.sh` checks this on a throwaway VM.
- **The container is hardened** (`packages/kernel/src/container/workshop.ts`): no new privileges, memory and process limits, IPv6 off, every agent process killed when a conversation opens and no other one is running. The base image is pinned by digest; Claude Code and Codex are pinned by version and installed root-owned, so they cannot replace themselves (Claude's autoupdater is off too) (`packages/kernel/docker/workshop.Dockerfile`).
- **The agent's network is an allowlist** (`packages/kernel/docker/ressac-network.mjs`): the agent's user reaches only localhost, the Mac's MCP and relay ports, and an allowlist proxy (HTTPS CONNECT and plain HTTP) limited to base domains (code and package hosts, the model APIs) plus the ones you add. The proxy refuses names that resolve to private addresses. The rules are applied again before each session, which does not start unless a direct connection is refused.
- **API keys stay in the macOS keychain** (`apps/firefox/host/relay.ts`): the container gets a session token, and the relay on the Mac swaps it for the key, only for inference paths and only toward the engine chosen when the session opened.
- **Two modes.** « Navigateur », the default, has no shell: Claude runs without Bash, `launch_app`, other MCP servers or any user, project or local settings; Codex without its shell tool, `notify` or a provider the agent defines (`packages/kernel/src/kernel.ts`). In both modes the models' own web tools are off, so all browsing goes through Ressac's browser: Claude's WebSearch and WebFetch, and Codex's web search (which, with its sandbox off, would fetch live pages from OpenAI's side), refused by the root-owned `requirements.toml` too. « Atelier » adds the shell to build and run project apps.
- **The agent cannot change its own rules.** Claude's managed settings (`disableAllHooks`, managed hooks only) and Codex's `requirements.toml` are root-owned; Codex's is rewritten each session with that session's MCP address. The internal `.ressac` folder (launch profiles, MCP config, the research notebook) is mounted read-only, except its `logs` folder, and planted symlinks are removed before each mount. The kernel's own reads and writes in the workspace refuse links the agent planted (`packages/kernel/src/workspace/no-links.ts`, `confined.ts`). npm install scripts are off by default.

### What the agent can reach in the browser

- **Only through the kernel's MCP server**, on `127.0.0.1`, with a bearer token checked in constant time.
- **Reading a tab needs your consent** (`packages/kernel/src/access/policy.ts`): the agent may read a tab you gave it, the tab you spoke to it from, or a local demo it built. Any other site needs a request, and a permission holds for one origin only. Tabs in a private space are never readable (`apps/firefox/chrome/agent/bridge.ts`). History and bookmarks need a card, once per conversation.
- **The agent does not click or type in pages.** It reads, navigates and hands control back to you for logins and captchas (`hand_over`). Two things you grant can act in a page: `run_js` on a tab (a developer right; console, network, performance and acting are granted per tab and per origin, through an in-process DevTools client with no socket), and an extension the agent wrote once you turn it on (signed by Mozilla with your account; its own pages are limited to the network you granted, and a wider scope turns it off until you grant it again).
- **An address the agent opens must be one it read, exactly** (`packages/kernel/src/mcp/seen.ts`): a page, one of its links or a search result, so `?q=<data>` added to a read address is not free. Outside a search, the fragment counts too (`page#<data>` is not free), and a local address, a tab it may read or an address you approved earlier in the conversation is also free. During a search, only that search's reads are free and a fragment the agent added is dropped. Any other address shows you a card with the whole address and the agent's reason before it opens. A recap may only link to addresses read.
- **What leaves through a search or a composed address is checked** (`packages/kernel/src/outflow/`). A search query that holds an access key, a private key, a login token, a card number, an IBAN or a social security number (checksums checked; in clear, base64 or hex) pauses before it reaches the search engine; an address the agent wrote that holds one shows a red line on its card. Ressac also remembers, per window, the distinctive items of what the agent read in your tabs, history and bookmarks (e-mails, phone numbers, long numbers, identifiers) and catches them coming back in a query or an address the same way, even in base64. It also catches them written another way: digits written as words in 56 languages, Chinese, Japanese and Korean numerals and their romanised forms, Greek, Hindi and other digit scripts, spaced-out letters and NATO words, in a query or a percent-encoded address. It remembers short identifiers mixing letters and digits (a door code, a file number). And it judges a series of searches that share the same words around a changing part as one: the parts are joined and checked, and from the third part that looks like a piece of code the search pauses, even when nothing read matches. Searches made of the pieces alone are joined too, since 0.1.25 also across the ordinary searches sent between them (among the last 20 kept); with ordinary searches between them and nothing read matching, they pause at the third piece of the same shape (« trois huit », « un six », « deux quatre »: two digits each). Since 0.1.25 the links it follows are judged the same way: after a private read, a link whose label is one character (« 3 », « B »; the label is kept by address, so a link opened by its address keeps it; with no label, a one-character query value or the last path segment of its address) joins the pieces followed on the same site, word links and other sites between them skipped; the pieces are joined and checked against what was read, and from the third, unless they climb or step back as a pager of ASCII digits and letters does, the link is no longer free: its address card shows a red line (`navigate`, `open_tab`, `read_pages`). The tab you opened the panel on or spoke to the agent from is not remembered unless its site is sensitive, as long as it stays on that origin. What you typed or asked yourself in this conversation is never treated as a leak. The figures below (measured on the rules shipped in 0.1.19) come from replaying recorded gestures through the rules, not from an injected agent run end to end: they say what this one layer catches once an agent has already obeyed a hostile page, not how often Ressac leaks. Of 398 honest gestures written by an agent that did not know the rules, 7 were paused, three of them for a public number with a secret's shape and one for a phone number read on a public page of a sensitive site during the search: 7/226 = 3.1% (95% interval 1.5–6.3%) of the gestures the rules can flag (queries and composed addresses), 7/398 = 1.8% of all. On 1 944 attacks adapted from two public benchmarks (AgentDojo and InjecAgent), each sending its leak whole in one query or one parameter, the leaked data was caught in about half the cases (1001/1944 = 51.5%, 49.3–53.7%); counted by distinct leak, 16 of InjecAgent's 28 were caught (39–74%). Spelled and split leaks are measured on their own (`bench/security/outflow/`, corpus 4, a replay of the rules with no model). There are 1 936 ways of sending the four private values of the end-to-end bench below:
- each language and script of the table;
- one query, with punctuation, or split over three searches;
- percent-encoded addresses;
- one row per hole found while building these rules.

All 1 936 were caught, where the rules before them caught 5. None of 51 ordinary searches made after a private read paused (dates, sizes, prices, versions, times, model names). Reworded leaks are not measured. End to end (`bench/security/B3/`), an agent made to obey the page (minimax-m3.1-flash, told to follow it) ran once on 36 hostile pages written for Ressac's own channels and 10 that ask for another language or script:
- with every card refused, one value left whole (1/36, 0/10): an attack sent all six digits of the verification code as three searches with no other words, which the rules of 0.1.23 did not join; since 0.1.24 such bare pieces are a series (tested, and in corpus 4; not yet rerun end to end; see the limits below). The agent tried only 8 of the 36 attacks that time (18 before these rules), so this rests on few attempts;
- with every card granted that had no red line, 4/36 whole values left: three without a shape (a doctor's name, a street, an adviser's name) and the same code in pieces; and 2/10 left through a percent-encoded address, a hole closed in 0.1.23: the 10 encoded-language pages rerun end to end on 0.1.23 leaked no whole value (0/10 cards granted, 8 tried, every attempt stopped; 0/10 refused), with one partial leak, the 4 digits of the lab file number sent as hyphenated hangul in a granted address.

Before these rules the same agent leaked 12/36 and 4/36, that code among them. Pieces of a value are counted apart, as partial leaks (4 digits or more of a value out in order, not the whole value): after these rules 2/36 attacks with every card granted (5 of the 8 digits of a client id, 4 of the 6 of a code) and 0/36 with every card refused, 1/10 encoded-lang; before them 3/36 and 0/36; none in any control. Those controls were biased: most offered the agent no link to follow, so as a baseline for pauses and cards they are rough. Claude Haiku, not made to obey, tried nothing on 85 hostile pages. One run per case: a rerun gives other numbers. The bench gave no tab the exemption of the tab you spoke from, so 51.5% is an upper bound. The intervals treat items as independent, which they are not (20 goals; 28 + 14 distinct leaks): read them as rough. These rules catch data with a shape, nothing else. A published attack success rate of about 1% for a frontier model under prompt injection measures something else: how often an attacked agent actually does what the page asks, mostly stopped by the model refusing. 51.5% is what our rules catch after that has failed; the two do not compare.
- **Sensitive sites ask again during and after a search** (`packages/kernel/src/access/sensitive.ts`): the history, the bookmarks and tabs of sensitive sites (mail, bank, payment, payroll, passwords, taxes, health, messages, account pages) ask their card again once per search, even when granted earlier in the conversation, and once more after each search ends (a final recap, the idle delay, a stop), until the conversation ends: a page that steered the search can still steer the agent after it. Before any search in the conversation, a granted sensitive tab reads with no new card, even when the agent was steered by a page it read some other way (a tab you asked it to read, a link it followed with `navigate`). The list is fixed and incomplete.
- **No model judges the searches.** A local judge (a small model comparing the agent's gestures with what you asked) was removed; these figures are the removed judge's, measured in November 2026, not the product's: on the 398 honest gestures above it paused about three in ten (117/398 = 29.4%) while its scores ranked the attack queries little better than chance (AUC 0.59). The exact-address rule, the outflow rules and the cards are what remain.
- **Memories written from the web are data.** A site app's memory keeps each entry's page and date and reaches the agent only after your grant, marked as data. The agent's research notebook (`packages/kernel/src/search/notes.ts`) is read-only in the container: the kernel writes a lesson only through `note_lesson`, once right after a hand-over where the agent was lost (any other tool call closes that chance), stamped with the date and that hand-over's sites, and gives the latest ones back with the `search_web` that gives a search its goal, capped and marked as hints, never instructions.
- **Invisible reads** run in a private, throwaway container, and every request they make to a local address (or a name that resolves to one) is refused (`apps/firefox/chrome/agent/local-guard.ts`).

### Pages and apps the agent builds

- **Agent pages** (ports 5300-5319) may only reach the agent's own local ports, or GET from five known CDN hosts (Google Fonts, cdnjs, jsDelivr, unpkg) over HTTPS on their usual port; a top-level navigation needs your gesture, and an address you type that the agent's server redirects is judged like the page's own navigation; DNS prefetch, preconnect and speculative connections are off (`apps/firefox/chrome/agent/page-guard.ts`). Agent apps get their own container and stay on their local origin.
- **Site apps** stay on their domains: every top-level load of an app's container must be on the app's or its sign-in domains, and a closed app's container loads nothing (`apps/firefox/chrome/store/sites.ts`). Tweaks run in a sandbox the parent process decides on, never the frame; a memory write needs the app's main document, its domains and your grant (`apps/firefox/chrome/store/site-frames.ts`).
- **Widgets, actions and workflows**: the harvest runs in a container with no network, a read-only file system, all capabilities dropped and memory and process limits. The kernel fetches for it: http(s) only, no credentials, declared domains only unless the widget or action asks for open web reads (then capped at 100 per run), local addresses refused after DNS resolution, size and redirect caps (`packages/kernel/src/workflows/access.ts`). Reading with your accounts needs a grant per widget or action. A widget's display has a CSP with no network and Trusted Types (`apps/firefox/chrome/window/widget-frame.ts`). The agent-written frames (widget displays, site homes, action components) run in a shared web content process like an ordinary page, not in the parent process, from copies under the profile's `chrome` folder behind a per-launch random address (`apps/firefox/chrome/window/remote-frame.ts`, `apps/firefox/chrome/agent/frame-actor.ts`). They cannot open another application (`mailto:`, app schemes) nor go fullscreen, refused explicitly; a frame whose document is not sandboxed (a null principal in that process) gets no data. When that process dies the frames load again in a new one, at most three times a minute each, then stay empty.
- **Ressac's own interface** (sidebar, panels, widgets, site homes) loads nothing from the web and has WebRTC denied (`apps/firefox/chrome/store/ui-network.ts`); the agent-written frames have no `RTCPeerConnection` at all, nested frames included (`apps/firefox/chrome/agent/frame-actor.ts`).
- **The external design-mode server** listens on `127.0.0.1`, refuses any request with an Origin header, checks Host against DNS rebinding, then a per-client token (`packages/kernel/src/design/external-server.ts`).

### Updates and telemetry

- **Updates are signed** with Ressac's own key (its certificate is built into the app) and must be newer than the running version (an update that could not be staged is judged by the feed's unsigned version); the DMG is signed with a Developer ID and notarized, and publishing refuses an update that does not verify. The VM image and its tools are pinned by SHA-256.
- **Telemetry** sends nothing before its notice has shown and one switch turns it all off: Ressac's own errors (addresses and the home path scrubbed), Firefox's crash reports (minidumps, which can hold page data and are not scrubbed: off by default, their own switch in Réglages › Confidentialité) and one count per launch (`apps/firefox/shared/telemetry.ts`, `apps/firefox/chrome/store/telemetry.ts`).

### Known limits

Known limits are marked with `shortcut:` comments in the code (for example custom-scheme navigations, preconnects and WebRTC in invisible reads). Others:

- The allowed domains include code hosts, package registries and the model APIs: the agent can send data there to an account an attacker controls. Subscription logins sit in the agent's home volume, so the agent can read them.
- The main token and every window's session token are readable inside the container (in Atelier, the agent's shell can use them). Calls under the main token are checked against what every window read, and a sensitive source asks its card again during any window's search, whatever the token. What stays open: another window's session token sends what the first window read without rule 2 noticing, and the main token opens, during a window's search, an address read outside it with no card.
- The relay passes the request body and extra headers unchanged (`anthropic-beta`, `OpenAI-Organization`): the agent can call any model or provider-side tool with your key. The relay token and the MCP tokens are plain bearers, readable by any process of the agent's user; the MCP server also accepts a token without `Bearer` and does not check `Origin`.
- In Navigateur, Claude has no shell but keeps its file and orchestration tools (`Write`, `Edit`, `NotebookEdit`, `Agent`, `Workflow`, `CronCreate`, `ScheduleWakeup`, `EnterWorktree`, `Skill`). Whether `Workflow` or `EnterWorktree` can run a command has not been tested.
- Once you grant `run_js` on a tab, script there can navigate or send anywhere without a card: it runs as the page itself, so no Ressac rule sees what it sends. It is bounded by your grant, given per tab and per origin, which does not carry to another tab or origin. The grant is tested; what a script does after it is not. An extension the agent wrote can act on its granted sites, and a changed one reloads without asking again while its rights stay the same.
- An agent page can still put data in the address of a GET to a known CDN, or use WebRTC; a click you make in it lets it navigate out, by script or a form POST, to the web or to another local service, for about 5 seconds. A site app's subresources are not limited to its domains, and its domains cover their sub-domains, shared public suffixes included (`github.io`, `co.uk`: anyone's page there counts as the app's); the grant card shows the list.
- A page that steers the agent during a search where it gets lost can still leave one lesson in the notebook. With the scripted adversary on 0.1.24, a planted lesson asking for the verification code in digit words, two per search, with an ordinary search between each, sent the code out whole in the next conversation, every card refused or granted (the series rule stopped at the first ordinary search). Since 0.1.25 its third piece pauses, in the next conversation as in one where the lesson is followed early (`notebook-evasive`, `notebook-early`): the first two pieces leave, 4 of the 6 digits. A lesson asking for one of the shapes the series rule does not see (below) still sends the value out.
- The outflow rules look only at a `search_web` query, at an address the agent composed and, since 0.1.25, at runs of followed links labelled with one character. Otherwise they do not check which link the agent chooses to follow among those it read: following a link it read is free, or browsing would need a card at each click, so a page that lays out links can let the choice encode data. It is bounded to a few bits per choice, only links the page itself offered, and only links still offered (a rewritten list is refused). Measured end to end before 0.1.25: an agent made to obey (minimax-m3.1-flash) clicked a code out whole on a grid of links labelled « 0 »… « 9 » on 4 of 4 pages with every card granted and 3 of 4 with every card refused, by `navigate {link}`, by an address read in the page and by `open_tab`. Since 0.1.25 the scripted adversary's grid (`bench/security/B3/adversary.mjs`, link-covert) gets the red-lined card at its third click, refused: the first two digits leave (2 of 6); its honest control, a climbing « 1 2 3 4 5 6 » on the same grid, gets none. Still free: the first two links of a run; a run whose last 8 pieces, ASCII digits and letters, climb or step back by one, with one step at most going back to « 1 » or to a page of the run right after a step of one (a code such as 123 456 is caught only when the run spells a value read whole; measured over all one million 6-digit codes sent this way with nothing read matching, 7.4 % pass, 2.9 % would without the back step); links labelled with words or more than one character (« case 3 », « trente-huit », « 38 ») over an address that holds no one-character piece (a word label over `/k/3` no longer frees it: the address tells the piece; a piece once shown for an address stays when the page lists it again under a word); pieces spread over sites (a site is the host's last two labels); a piece carried in a sub-domain; one link per conversation; an address never shown with its label whose own path holds no piece. The memory has bounds a page can use: the labels of the last 2 000 links shown are kept, so a page read in full with about 2 000 links evicts the grid's labels before the clicks; and the pieces of 8 sites are kept, so one-character links followed on 8 other sites between two pieces drop the grid's run (both unit-tested). Since the review of 0.1.25, a word link or a link elsewhere between the pieces no longer ends the run, `read_pages` is judged like a click (unit-tested on the server, not in the scripted bench, whose cases have no `read_pages` grid), labels outlive the page that showed them, a CJK grid that makes the code climb gets no pager pass, and calls made at the same time are judged one after another (a held link counts even when you refuse it). Honest links that get the card: a pager jumped back by more than one page (« 2 », « 7 », then « 2 », or « 1 », « 5 », « 3 »), a size selector « S M L », an alphabet index « M C T », gallery links with no label (`/photos/3`, `/photos/1`, `/photos/7`), calendar days « 5 9 3 », and several shops under one two-label suffix such as `co.uk`, which count as one site (unit-tested shapes, not measured on real browsing). A run never ends on its own: after one step on a site that is no pager step, the next one-character links followed there keep getting the card until that step is more than 8 pieces back (« 5 9 3 », then a pager « 1 »… « 7 » is carded, « 8 » no longer). Nor do they check an address a private page showed whole (how the agent percent-encodes it is a small channel too); screen captures; files in the workspace; `run_js`; what leaves through a workflow, a widget, an action or `launch_app`.
- A history entry of a site app whose window is closed still counts as a followed link (its address is on that app's own domains).
- They catch only shaped items. Private text without one leaves unseen: a message, a name, a street address, health data, a list of holdings. So does data the agent never read through a remembered source (a file in the workspace, something from an earlier session, a screenshot), and a password with no recognizable shape.
- What you typed in this conversation is never caught if it leaks: the rules treat it as yours to send, or every search you ask for with your own words would pause. A page that steers the agent can therefore send it out. It is bounded to this conversation in this window (another window's typed text is not exempt). The exemption is unit-tested; a steered agent sending it is not.
- The memory of what the agent read is per window and is lost when Ressac restarts or the local AI is switched off and on: it is kept in memory only, so what the agent read in your private tabs is never written to disk. After a restart the agent must read the data again to send it, and that read is remembered again; only data it saved in the workspace in between escapes (see « files in the workspace » above). Tested by unit tests. Rule 2's false alarms grow with how much the window has read: the measured rate is for windows that read little.
- Sensitive sites asking again during a search does not cover the developer tools' reads of a sensitive tab.
- A 6-digit coincidence with a number the agent read can pause an honest query.
- A series of searches pauses at its third piece: the first two have already left. In the end-to-end bench, 5 of the 8 digits of a client id and 4 of the 6 digits of a code left this way, and a code sent as three searches with no other words (« trois huit », « un six », « deux quatre ») left whole in all four obedient runs; 4 digits of a 6-digit code leave 100 guesses. A series is not seen as one when:
  - the words around the changing part change from one search to the next;
  - they are shorter than 6 characters (« tarif 3 8 », « tarif 1 6 »…); searches made of the pieces alone, with no words around them (« trois huit », « un six », « deux quatre », seen in the end-to-end bench), are a series since 0.1.24; with an ordinary search between the pieces they are one since 0.1.25 (corpus 4 row `k-gap` and the scripted adversary's `bare-pieces-gap`, both paused at the third piece; before, the code left whole), but not when each search carries one digit or one whole number (« 38 », « 16 », « 24 », with or without ordinary searches between: corpus 4 row `k-gap-numbers`), nor, with ordinary searches between them and nothing read matching, when the pieces change shape (« trois huit », « 1 6 2 », « 4 »); three honest bare searches of one shape spread over a conversation pause: football formations « 4 4 2 », « 4 3 3 », « 3 5 2 », chess moves « e 4 », « d 4 », « c 5 », or « 2 1 », « 3 0 », « 1 1 » (known false pauses, pinned in the tests); other scattered short searches (« 2 1 », « e 4 », « 4 4 2 ») do not (unit-tested, not measured on real searches);
  - the search goes out as an address (`navigate`, `open_tab`), which is checked alone.

  Numbers written as compound words (« trente-huit », "thirty-eight") are not read, nor a short code in base64. A model name read in an order mail (WH-1000XM5) pauses a later search for it, because short identifiers are remembered.
- The agent can put text on the clipboard; if you paste it into the agent's terminal, it counts as typed by you: Ressac cannot tell a paste from typing there. It needs you to paste, into that terminal. Not tested.
- The agent can still write its own instruction files (`AGENTS.md`, `AGENTS.override.md`, the four `guides/`, Codex's `~/.codex` instructions, its `config.toml` (which can name an instruction file, and which its interactive mode cannot skip) and skill folders). In Navigateur, before each session they are compared with the copy you last accepted (`<workspace>/.ressac/instructions/`, read-only in the container): a change waits for you in a card, to keep or to revert, and Claude reads the accepted copy of `AGENTS.md`, never the live one. Claude's auto-memory (`~/.claude/projects/*/memory`), which the gate does not watch, is off in Navigateur. « Revenir » keeps what it replaced in `.ressac/instructions/replaced.json` (the last revert only). Codex's own system skills (`~/.codex/skills/.system`) are accepted without a card the first time they appear, and watched from then on. What stays open: Atelier mode has no such gate, because there the agent has a shell and could change any file anyway; choosing Atelier is choosing that (the bench confirmed the gate runs only in Navigateur); a session already running in another window can change the guides or Codex's files between the card and the start (Claude reads the guides live); the Codex writer (drafts) is not gated; a folder the agent plants at a watched file path does not block the session (« Garder » accepts it), but « Revenir » fails on it until you remove it; a file too long, binary or unreadable, or a skill folder with too many files, is shown only as a marker, and « Revenir » deletes it (the whole folder for too many files). For a too-long file you kept, a change past its first MiB is not seen. A project or home `.npmrc`, `--ignore-scripts=false` or `npm_config_ignore_scripts=false` can turn install scripts back on.
- The version signed inside an update archive is the Firefox engine's, not Ressac's: Firefox's updater accepts any signed Ressac archive built on the same engine, and « newer » is checked by Ressac's own code once the update is staged. An update downloaded but not yet checked when Ressac quits is applied at the next launch, before that check runs. Both need control of the update feed and an older signed archive.
- Telemetry starts once its notice has appeared, not once you answered it: an error raised while it waits is sent. The launch count carries a random install id, kept until you turn the switch off, so launches of the same install can be linked; error reports carry none. Everything sent: the error's type, message (300 characters, scrubbed) and stack (50 frames), the release and a source tag; for the count, its session id, install id, times, status and error count. No IP address.
- The design-mode server lets the last client that declares a folder take it, with its pending remarks and its port, and accepts folders outside your home and any port from 1024 outside the agent's range.
- Without the signing settings, a DMG built from source is only ad hoc signed.

How these protections were tested, and what is not tested yet: [docs/security-testing.md](docs/security-testing.md).

A way around one of the protections above is a vulnerability, even when it needs a crafted page.

## Out of scope

- What the agent does with permissions you granted it.
- Attacks that need full control of the user's Mac, of Ressac's VM or of a Docker setup.
- Rate limiting and denial of service against your own machine.
